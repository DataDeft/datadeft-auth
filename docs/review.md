## Suggested order

1. Row 1 first — one line per method now, a breaking API change later.
2. Row 22 next — redacted `Debug` is a small, high-impact secret-exposure fix.
3. Rows 4 + 5 + 8 + 26 batched into one quick-win PR (5 and 8 share the
   validating constructor; 26 keeps fake behavior aligned while touching session
   expiry policy).
4. Rows 9–11 next — all three change which error surfaces where, and get more
   expensive to change once an app depends on the current mappings.
5. Row 23 is the scanner-safe flow-state design gap; decide before exposing the
   landing helper as a blessed production path.

   Lambda behind API Gateway the inline send may be acceptable, but quota-burn
   and burn-before-session-create should be deliberate choices, not accidents.
7. Row 25 is a small Axum API ergonomics cleanup before route examples spread.
8. Rows 12–21 are internal quality; 21 + 18 + 19 make one cheap cleanup PR,
   13 + 17 one hot-path PR, 12 + 15 + 16 one structure PR, 20 a test-only PR.

   consume-condition fix, and 27 (the `validate_session` entrypoint) closes
